# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Architecture

Content-driven single-page portfolio, React 18 on Vite 7. All components are **function components**; content lives in data files and flows down through props — edit data, not components, to change the site. No CSS-in-JS or UI-kit library: plain per-component `.css` plus CSS variables.

**Render flow:** [index.js](src/index.js) (`applyTheme(chosenTheme)` before render, `createRoot`, `HelmetProvider`) → [App.js](src/App.js) (passes `chosenTheme` down as `theme`) → [Main.js](src/containers/Main.js) (react-router-dom 7 `HashRouter`, hash routes e.g. `/#/home`, every page `React.lazy`-loaded). `/` redirects to `/home` (or `/splash` when `settings.isSplash`). All pages except Splash are children of the layout route [PageLayout.js](src/components/pageLayout/PageLayout.js) (Header + `<main>` with `Suspense`/`<Outlet/>` + TopButton, mounted once; moves focus to `<main>` on user navigation); `Error404` is the catch-all.

**SEO:** [SeoHeader.js](src/components/seoHeader/SeoHeader.js) (rendered inside Header) sets the default `<title>` + JSON-LD Person; each page under PageLayout sets its own title with [PageTitle.js](src/components/seoHeader/PageTitle.js). Splash sits outside the layout route, so it gets neither and keeps the static `<title>` from `index.html`. Description/Open Graph meta are static in [index.html](index.html) — keep its description in sync with `greeting.subTitle` and its `<title>`/`og:title` in sync with `seo.title` by hand (sub-page titles are `<Page> | ${seo.brand}`). Every absolute site URL (`seo.og.url` in portfolio.js, which also feeds JSON-LD `url`; `og:url`/`og:image` in index.html) must use `https://portfolio.yamiannephilim.com/` — the apex/`www` domain is only a Worker redirect.

**Content sources:**

- [src/portfolio.js](src/portfolio.js) — central config. Exports `settings` (`{isSplash}`), `seo`, `greeting`, `socialMediaLinks`, `skills`, `competitiveSites`, `certifications`, `experience`, `projectsHeader`, `contactPageData`.
- [src/shared/opensource/projects.json](src/shared/opensource/projects.json) — static snapshot feeding the Projects page (the only file left in that folder); nothing is fetched at runtime.

**Theming:** [src/theme.js](src/theme.js) defines 14 palettes; `chosenTheme` (currently `blueTheme`) selects the active one. `applyTheme()` writes `--color-body`, `--color-text`, `--color-secondary-text`, `--color-highlight`, `--color-header` on `<html>` — that variable set is the contract component CSS relies on; components also get `theme` as a prop for inline colors. [src/base.css](src/base.css) holds the global reset/body colors and `:root` fallbacks equal to `chosenTheme` (correct first paint before JS) — changing `chosenTheme` means updating that block too, or [theme.test.js](src/theme.test.js) fails.

**In-house UI pieces:** [Tooltip.js](src/components/tooltip/Tooltip.js) (portal to `<body>`, hover + keyboard focus, Escape to dismiss; ids via [toDomId](src/utils/domId.js)); the Experience accordion is native `<details>`/`<summary>` ([ExperienceAccordion.js](src/containers/experienceAccordion/ExperienceAccordion.js)); social/top-button icons are inline SVG in [src/components/icons/](src/components/icons/) — a new social network needs a path in `brandIcons.js` plus an entry in the `Map` in [SocialMedia.js](src/components/socialMedia/SocialMedia.js). Scroll animations: react-awesome-reveal + `@emotion/react`.

**Skill icons:** [SoftwareSkill.js](src/components/softwareSkills/SoftwareSkill.js) has two modes — `fontAwesomeClassname` → Iconify (deferred CDN `<script>` in `index.html`), or `imageSrc` → `public/skills/*.webp` loaded as `${import.meta.env.BASE_URL}skills/<img>?v=${skillAssetVersion}`. How to produce the 96px WebP files: [assets-src/README.md](assets-src/README.md).

**Site icons:** `public/icons/*` are generated by [scripts/generate-icons.py](scripts/generate-icons.py) with the exact filenames `index.html` and `public/manifest.json` reference — regenerate, don't rename by hand. The share preview (`og:image`) is [public/og-image.png](public/og-image.png) (1200×630), rendered from [assets-src/og-image.html](assets-src/og-image.html) (render command in [assets-src/README.md](assets-src/README.md)); it embeds `android-icon-512x512.png` and the `greeting.subTitle` text, so re-render it when either changes.

## Commands (build / test / run)

```bash
npm ci                                      # install exactly per package-lock (engines: Node ^22.13.0 || >=24; Docker/CI use 22)
npm run dev                                 # Vite dev server on :3000
npm run lint                                # ESLint over src/**/*.js only
npm test                                    # vitest run — single run
npm run test:watch                          # vitest in watch mode
npm run build                               # vite build -> build/
npm run preview                             # serve the production build locally
npx vitest run cloudflare                   # Worker tests only
python3 scripts/generate-icons.py <photo>   # regenerate public/icons/* (needs Pillow; flags in the script docstring)
```

There is no `deploy` script and no `npm start`. `npm test` picks up 6 files: `src/App.test.js`, `src/theme.test.js`, `src/containers/Main.test.js`, `src/components/header/Header.test.js`, `src/components/tooltip/Tooltip.test.js`, `cloudflare/redirect-worker.test.js` — UI coverage is still thin, so a green run is not proof a UI change works. If `npm ls` reports invalid/extraneous packages, `node_modules` is stale versus the lockfile: run `npm ci` before trusting lint/test/dev results.

## Deployment

- [Dockerfile](Dockerfile): `node:22-alpine` stage runs `npm ci` → `COPY . .` → `node scripts/verify-lfs-assets.js` → `npm run lint && npm test` → `npm run build`; `nginx:1.27-alpine` serves `build/` on :80 with a `HEALTHCHECK` on `/healthz`.
- [.dockerignore](.dockerignore) filters that build context (drops `.git`, `.github`, `.husky`, `docs`, `scripts/server`, `node_modules`, `build`, `.env*`). Lint/test run inside it, so they must not depend on excluded paths, and everything they need (`src/`, `public/`, `cloudflare/`, `index.html`, `vite.config.js`, ESLint config, `nginx.conf`, `scripts/verify-lfs-assets.js`) must stay included — otherwise CI's `test` job passes but every Docker build fails. Never let `.env*` into the image.
- [nginx.conf](nginx.conf): SPA fallback, gzip, `/healthz` (200, `no-store`); `index.html`/`manifest.json`/`robots.txt` are `no-cache`; `/assets/` and `/skills/` are cached 1 year `immutable`; other static files 7 days.
- GitHub Actions ([.github/workflows/](.github/workflows/)):
  - `ci.yml` — push to `main`/`develop` and every PR: verify assets, lint, test, build, Docker build (no push).
  - `deploy.yml` — push to `main` or manual run (optional `image_tag` to redeploy/rollback), gated by repo variable `DEPLOY_ENABLED`: builds `yamiannephilim/portfolio:latest` + `:sha-<7>`, then a **self-hosted runner on the home server** restarts container `yan-portfolio` on network `yan`, waits for healthy, rolls back on failure, notifies Telegram. The container name is a contract with the Cloudflare Tunnel (container `cloudflare-tunnel-yan`, ingress `portfolio.yamiannephilim.com` → `http://yan-portfolio:80`, managed in the Zero Trust dashboard) — renaming it without changing the ingress takes the site off the tunnel.
  - `deploy-worker.yml` — push to `main` touching `cloudflare/**` or the workflow file itself, or a manual run, gated by `WORKER_DEPLOY_ENABLED`: tests the Worker, `npx wrangler@4 deploy`, confirms via `wrangler deployments status --json` that the new `Current Version ID` serves 100%, then smoke-tests the apex domain. Cloudflare bot protection blocks GitHub-hosted runner IPs at the edge (`403`, no `Location`), so that case is only a warning — the API step proves the version, not Page Rules/Redirect Rules, so after that warning check `curl -sI https://yamiannephilim.com` by hand. Don't "fix" it by spoofing a browser, loosening zone security, or moving the job to the self-hosted runner (its guard hook only admits `deploy.yml`).
  - Every deploy job also requires `github.ref == refs/heads/main`. With the gates enabled, **a merge to `main` is a production deploy**, and any change on `main` under `cloudflare/**` (or to `deploy-worker.yml`) redeploys the live Worker.
- GitHub Actions is the only deploy path (Jenkins was retired and `Jenkinsfile` deleted). Secrets, first-time setup, rollback and runner details: [docs/DEPLOY.md](docs/DEPLOY.md).

**Domain failover:** [cloudflare/redirect-worker.js](cloudflare/redirect-worker.js) (Worker `yan-failover-redirect`; the old time-based `yan-schedule-redirect` was deleted) 302-redirects apex/`www` `yamiannephilim.com` to `https://portfolio.yamiannephilim.com` while a probe of `/healthz` succeeds, and to `https://github.com/Tynab` only when the origin is unreachable (network error, >3 s, or 502–504/520–526/530); probe results are memoized 30 s per isolate. `www…/wedding-card` always goes to its own target. There is no time-of-day schedule: the domain pointing at GitHub means the origin failed a probe. A deploy or rollback restarts the container, so a GitHub redirect for up to ~30 s afterwards is normal — check `docker ps` and `/healthz` before calling it an outage. Details: [cloudflare/README.md](cloudflare/README.md).

- The old Page Rules (301 forwarding for wedding-card/`www`/apex) were retired in favour of the Worker; never reintroduce 301s for these hosts (browsers cache them permanently). A static fallback, if ever needed, is a `302` Redirect Rule.
- Redirects must stay `302` + `Cache-Control: no-store` (a 301 is cached permanently and would strand visitors on GitHub after recovery). Change targets only in the `// ===== Cấu hình (chỉ sửa ở đây) =====` block; the same URLs (no trailing slash) are hard-coded in `redirect-worker.test.js` and in the smoke-test `case` of `deploy-worker.yml` — update all three in one commit.
- Changing `name` in wrangler.toml creates a new Worker while the routes stay on the old one — follow "Đổi tên Worker" in cloudflare/README.md (upload without routes → repoint routes → delete the old Worker) instead of just editing the name.
- Routes live in [wrangler.toml](cloudflare/wrangler.toml). The zone-scoped CI token only **adds** routes, never removes them: to remove one, delete it on the dashboard (Worker → Settings → Domains & Routes) **and** in wrangler.toml, or the next deploy re-attaches it. The `portfolio.yamiannephilim.com/*` pass-through route stays commented out unless verified per cloudflare/README.md ("Route tùy chọn").
- Once deployed via wrangler/CI, don't edit Worker code in the Cloudflare dashboard (the next deploy overwrites it); after a dashboard/`wrangler rollback`, also revert the git commit or the next CI deploy brings the code back.

## Coding conventions

- Every self-authored source, config, script and workflow file carries a Vietnamese `Tóm tắt:` summary comment (`//` or `/* … */` in JS — in components usually right above the main function; `#` at the top of YAML/shell/Python). CSS files open with a `/* … */` header describing the stylesheet. Match this when adding files. Exceptions: the one-line `.husky/pre-commit`, `index.html`, GitHub's template `.github/FUNDING.yml`, and the plain pattern/ignore files (`.gitattributes`, `.gitignore`, `.eslintignore`, `public/robots.txt`).
- Formatting is tool-enforced: `.husky/pre-commit` runs `lint-staged` (prettier on staged `*.{js,css,md}`, `prettier-package-json` on `package.json`). Don't hand-format.
- ESLint config is standalone ([.eslintrc.cjs](.eslintrc.cjs): `eslint:recommended` + `plugin:react/recommended` + `plugin:react-hooks/recommended`, `react/prop-types` off, Vitest globals declared for `*.test.js`).
- Colors that should follow the theme come from `var(--color-*)` (or the `theme` prop inline). Some neutral colors are fixed on purpose (black/white tooltip, white/gray certification-card text and border, GitHub-style grays in GithubRepoCard.css, shadows/overlays) — "no literal colors in CSS" is not a rule.
- Accessibility is the default: interactive elements are real `<button>`s/links with ARIA state, decorative icons are `aria-hidden`, tooltips go through `Tooltip`.
- New route page: put it under `src/pages/`, `React.lazy`-import it in `Main.js` as a child of the `PageLayout` route, and render `<PageTitle title="…" />`.
- `.gitattributes` forces LF for `*.sh`, `*.conf`, `Dockerfile` (they run on Linux) and marks images/fonts `binary`.

## Rules when editing code

- **Routes vs nav:** Header links Home / Certifications / Experience / Projects / Contact. `/education` only redirects to `/certifications` (kept for old links); the Opensource page no longer exists. Splash is off (`isSplash: false`). The Certifications page renders CompetitiveSites + Certifications (no degrees).
- **Skill images:** files are requested as `skills/<imageSrc>?v=${skillAssetVersion}` and nginx caches `/skills/` `immutable` for a year. Overwriting or re-encoding a file under the same name **requires** bumping `skillAssetVersion` in [SoftwareSkill.js](src/components/softwareSkills/SoftwareSkill.js), or returning visitors keep the old image. A new filename is already a new URL (the code comment asks for a bump on every add too — harmless).
- **Reveal animations (react-awesome-reveal):** every `<Fade>` must keep `triggerOnce` — without it, elements re-hide and re-animate each time they cross the viewport, which caused violent scroll juddering (all 18 current usages have it). `Fade` wraps each child in its own `<div>`: when the animated element is a flex/grid item, put the sizing class on the Fade itself via `className` (see `.cert-card-reveal` in [CertificationCard.js](src/components/certificationCard/CertificationCard.js)) — sizing only the inner element collapses the layout.
- **Typography and text colours are owner-approved — don't drift them in refactors or a11y passes.** Font faces/weights/sizes match the July 2026 production build (Google Sans faces from `src/assests/fonts/`, Agustina logo, system font for body text, Experience accordion content at 14px/20px with descriptions in the system font, 404 page in the system font, tablet header at 12px). The secondary text colour stays `#7F8DAA` (~3.1:1 on the body, below WCAG AA) by the owner's choice — propose contrast changes, never apply them unasked. When replacing a component or library, compare rendered fonts before/after (e.g. headless Chrome `CSS.getPlatformFontsForNode`) instead of assuming equivalence.
- **Line height:** `body` uses an absolute `line-height: 23px` ([index.css](src/index.css)); any class with `font-size` above 23px must set its own `line-height` (~1.2) or wrapped lines overlap.
- **No Git LFS:** binaries are plain Git blobs (the account's LFS quota is exhausted) — never re-add `filter=lfs` rules. [scripts/verify-lfs-assets.js](scripts/verify-lfs-assets.js) stays as a guard: Docker/CI builds fail if anything in `public/` or `src/assests/` is an LFS pointer (stale or broken checkout).
- **`.js` files hold JSX.** [vite.config.js](vite.config.js)'s `jsAsJsx` plugin (`enforce: "pre"`) esbuild-transforms every `.js` under `src/` (path-prefix match, not RegExp) as JSX before Rollup's import analysis; `optimizeDeps.esbuildOptions.loader` does the same for dev dependency scanning. Keep new component files under `src/` as `.js`; files outside `src/` (e.g. `cloudflare/`) are not JSX-transformed.

## Do not change on your own

- **`src/assests/` is misspelled on purpose** (not `assets`) and referenced that way everywhere — renaming it breaks every import.
- **`vite.config.js`'s `base: "./"` + `build.outDir: "build"`** control relative asset paths and output location (Dockerfile/nginx expect `build/`). Vite ignores package.json's `"homepage": "."`, a harmless CRA leftover — don't rely on it and don't "clean it up" without checking both files stay consistent.
- **No `overrides` in package.json:** old hard pins blocked newer security fixes. Prefer `npm update <pkg>`; if an override is unavoidable, use a range (`^x.y.z`) and run `npm audit` after every lockfile change.
- **Vite stays on v7.** Vite 8 switches to the rolldown/oxc toolchain and drops the bundled esbuild that `jsAsJsx` depends on — upgrading broke both build and tests when tried. Don't bump the Vite major (and never run `npm audit fix --force`, which force-installs Vite 8) without first migrating the JSX-in-`.js` handling.
- **No service worker** (`src/serviceWorker.js` was deleted) — reintroducing one would break the no-cache/deploy expectations baked into `nginx.conf`.
- **Deploy security (public repo + self-hosted runner = root-equivalent on the home server):**
  - Never add `pull_request`/`pull_request_target` triggers to `deploy.yml`, and never use the `portfolio`/`self-hosted` runner labels in a PR-triggered workflow. The file can't protect itself (a fork PR can add its own workflow targeting the label); the real guards are the repo setting "Require approval for all external contributors" (never approve a fork-PR run touching `.github/`), branch protection on `main`, and the server-side hook — see docs/DEPLOY.md §8.
  - The root-owned hook `/usr/local/libexec/gha-runner-guard.sh` (installed by [scripts/server/install-runner.sh](scripts/server/install-runner.sh), not editable from the repo) rejects every job that isn't a `push`/`workflow_dispatch` on `refs/heads/main` from exactly `.github/workflows/deploy.yml`. Renaming `deploy.yml` or moving the self-hosted job breaks every production deploy until the hook is reinstalled.
  - Keep the self-hosted `deploy` job free of `actions/checkout` and third-party actions; pass dynamic values via `env:`, never by interpolating `${{ }}` into `run:` scripts. `build-push` outputs only the tag — an output containing the `DOCKERHUB_USERNAME` secret is masked to an empty string.
  - On the server never use `docker container/image/system prune` — remove only the `yan-portfolio` container and `yamiannephilim/portfolio` images (the server also runs other, unrelated containers, including the Cloudflare Tunnel).

# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Architecture

Content-driven single-page portfolio, React 18 on Vite 7, deployed as static files on **Cloudflare Pages** at the apex `https://yamiannephilim.com/`. All components are **function components**; content lives in data files and flows down through props — edit data, not components, to change the site. No CSS-in-JS or UI-kit library: plain per-component `.css` plus CSS variables. There is no Docker, nginx, Cloudflare Tunnel, self-hosted runner or Worker in the current architecture.

**Render flow:** [index.js](src/index.js) (`applyTheme(chosenTheme)` before render, `createRoot`, `HelmetProvider`) → [App.js](src/App.js) (passes `chosenTheme` down as `theme`) → [Main.js](src/containers/Main.js) (react-router-dom 7 `HashRouter`, hash routes e.g. `/#/home`, every page `React.lazy`-loaded). `/` redirects to `/home` (or `/splash` when `settings.isSplash`). All pages except Splash are children of the layout route [PageLayout.js](src/components/pageLayout/PageLayout.js) (Header + `<main>` with `Suspense`/`<Outlet/>` + TopButton, mounted once; moves focus to `<main>` on user navigation); `Error404` is the catch-all.

**SEO:** [SeoHeader.js](src/components/seoHeader/SeoHeader.js) (rendered inside Header) sets the default `<title>` + JSON-LD Person; each page under PageLayout sets its own title with [PageTitle.js](src/components/seoHeader/PageTitle.js). Splash sits outside the layout route, so it gets neither and keeps the static `<title>` from `index.html`. Description/Open Graph meta are static in [index.html](index.html) — keep its description in sync with `greeting.subTitle` and its `<title>`/`og:title` in sync with `seo.title` by hand (sub-page titles are `<Page> | ${seo.brand}`). Every absolute site URL (`seo.og.url` in portfolio.js, which also feeds JSON-LD `url`; canonical/`og:url`/`og:image` in index.html) must use `https://yamiannephilim.com/`. Never reintroduce `portfolio.yamiannephilim.com` or any other portfolio subdomain.

**Content sources:**

- [src/portfolio.js](src/portfolio.js) — central config. Exports `settings` (`{isSplash}`), `seo`, `greeting`, `socialMediaLinks`, `skills`, `competitiveSites`, `certifications`, `experience`, `projectsHeader`, `contactPageData`.
- [src/shared/opensource/projects.json](src/shared/opensource/projects.json) — static snapshot feeding the Projects page (the only file left in that folder); nothing is fetched at runtime.

**Theming:** [src/theme.js](src/theme.js) defines 14 palettes; `chosenTheme` (currently `blueTheme`) selects the active one. `applyTheme()` writes `--color-body`, `--color-text`, `--color-secondary-text`, `--color-highlight`, `--color-header` on `<html>` — that variable set is the contract component CSS relies on; components also get `theme` as a prop for inline colors. [src/base.css](src/base.css) holds the global reset/body colors and `:root` fallbacks equal to `chosenTheme` (correct first paint before JS) — changing `chosenTheme` means updating that block too, or [theme.test.js](src/theme.test.js) fails.

**In-house UI pieces:** [Tooltip.js](src/components/tooltip/Tooltip.js) (portal to `<body>`, hover + keyboard focus, Escape to dismiss; ids via [toDomId](src/utils/domId.js)); the Experience accordion is native `<details>`/`<summary>` ([ExperienceAccordion.js](src/containers/experienceAccordion/ExperienceAccordion.js)); social/top-button icons are inline SVG in [src/components/icons/](src/components/icons/) — a new social network needs a path in `brandIcons.js` plus an entry in the `Map` in [SocialMedia.js](src/components/socialMedia/SocialMedia.js). Scroll animations: react-awesome-reveal + `@emotion/react`.

**Skill icons:** [SoftwareSkill.js](src/components/softwareSkills/SoftwareSkill.js) has two modes — `fontAwesomeClassname` → Iconify (deferred CDN `<script>` in `index.html`), or `imageSrc` → `public/skills/*.webp` loaded as `${import.meta.env.BASE_URL}skills/<img>?v=${skillAssetVersion}`. Cloudflare Pages/CDN may cache `/skills/` per deployment, so bump `skillAssetVersion` whenever a skill image is added or overwritten. How to produce the 96px WebP files: [assets-src/README.md](assets-src/README.md).

**Site icons:** `public/icons/*` are generated by [scripts/generate-icons.py](scripts/generate-icons.py) with the exact filenames `index.html` and `public/manifest.json` reference — regenerate, don't rename by hand. A default run also writes `public/favicon.ico`, because Pages has no nginx alias for the root path. The share preview (`og:image`) is [public/og-image.png](public/og-image.png) (1200×630), rendered from [assets-src/og-image.html](assets-src/og-image.html) (render command in [assets-src/README.md](assets-src/README.md)); it embeds `android-icon-512x512.png` and the `greeting.subTitle` text, so re-render it when either changes.

## Commands (build / test / run)

```bash
npm ci                                      # install exactly per package-lock (engines: Node ^22.13.0 || >=24; CI/Pages use 22)
npm run dev                                 # Vite dev server on :3000
npm run lint                                # ESLint over src/**/*.js only
npm test                                    # vitest run — single run
npm run test:watch                          # vitest in watch mode
npm run build                               # vite build -> build/
npm run preview                             # serve the production build locally
python3 scripts/generate-icons.py <photo>   # regenerate public/icons/* + public/favicon.ico (needs Pillow)
```

There is no `deploy` script and no `npm start`. `npm test` picks up 6 files: `src/App.test.js`, `src/theme.test.js`, `src/containers/Main.test.js`, `src/components/header/Header.test.js`, `src/components/tooltip/Tooltip.test.js`, `src/seo.test.js` — UI coverage is still thin, so a green run is not proof a UI change works. If `npm ls` reports invalid/extraneous packages, `node_modules` is stale versus the lockfile: run `npm ci` before trusting lint/test/dev results.

## Deployment

- **Cloudflare Pages Git integration** is the only deploy path. Project settings: repository `Tynab/yan-portfolio`, production branch `main`, build command `node scripts/verify-lfs-assets.js && npm run build`, build output directory `build`, environment variable `HUSKY=0`, no `NODE_VERSION` pin unless the build-image default stops satisfying `engines`, and no `functions/`.
- **Branch protection on `main`** must require the CI check `Lint, test & build` and block direct pushes. Pages has no `DEPLOY_ENABLED` gate, so a merge to `main` is a production deploy; branch protection is the only gate.
- [.github/workflows/ci.yml](.github/workflows/ci.yml) only runs verify-assets, lint, test and build on pushes/PRs. There is no `deploy.yml` or `deploy-worker.yml`.
- **Canonical host:** apex `https://yamiannephilim.com/`. `www.yamiannephilim.com` is a Cloudflare Single Redirect to the apex (**302**, path + query preserved); `wedding-card.yamiannephilim.com` is a separate host rule (**302** → `https://tynab.github.io/Yami-Buzzy`, query discarded). Keep the wedding-card rule first for clarity; it does not overlap the `www` catch-all. The old `www…/wedding-card` path is not an exception anymore — it follows the `www` catch-all to the apex.
- **`portfolio.yamiannephilim.com` is gone on purpose:** no DNS record, no Worker route, no redirect. Don't recreate it in code, docs, or Cloudflare.
- **No Worker:** there is no health probe or failover. Redirects are pure Cloudflare Redirect Rules. Never reintroduce a Worker for static hosting.
- **No `public/_headers`, `_redirects` or `404.html`** without a tested reason. Pages' default SPA fallback relies on the absence of a top-level `404.html`; don't port nginx's `immutable` headers blindly. If `_headers` is ever needed, keep it narrow and do not add a strict CSP while AdSense/gtag/Iconify inline scripts exist.
- **Rollback:** Pages deployment rollback or `git revert` on `main`. The old Docker origin has been removed; there is no container rollback path.
- Manual cutover, redirect rules, decommission checklist and secrets to revoke: [docs/DEPLOY.md](docs/DEPLOY.md). The old Docker runbook is archived at [docs/legacy/DEPLOY-docker.md](docs/legacy/DEPLOY-docker.md).

## Coding conventions

- Every self-authored source, config, script and workflow file carries a Vietnamese `Tóm tắt:` summary comment (`//` or `/* … */` in JS — in components usually right above the main function; `#` at the top of YAML/shell/Python). CSS files open with a `/* … */` header describing the stylesheet. Match this when adding files. Exceptions: the one-line `.husky/pre-commit`, `index.html`, GitHub's template `.github/FUNDING.yml`, and the plain pattern/ignore files (`.gitattributes`, `.gitignore`, `.eslintignore`, `public/robots.txt`).
- Formatting is tool-enforced: `.husky/pre-commit` runs `lint-staged` (prettier on staged `*.{js,css,md}`, `prettier-package-json` on `package.json`). Don't hand-format.
- ESLint config is standalone ([.eslintrc.cjs](.eslintrc.cjs): `eslint:recommended` + `plugin:react/recommended` + `plugin:react-hooks/recommended`, `react/prop-types` off, Vitest globals declared for `*.test.js`).
- Colors that should follow the theme come from `var(--color-*)` (or the `theme` prop inline). Some neutral colors are fixed on purpose (black/white tooltip, white/gray certification-card text and border, GitHub-style grays in GithubRepoCard.css, shadows/overlays) — "no literal colors in CSS" is not a rule.
- Accessibility is the default: interactive elements are real `<button>`s/links with ARIA state, decorative icons are `aria-hidden`, tooltips go through `Tooltip`.
- New route page: put it under `src/pages/`, `React.lazy`-import it in `Main.js` as a child of the `PageLayout` route, and render `<PageTitle title="…" />`.
- `.gitattributes` forces LF for `*.sh` and marks images/fonts `binary`.

## Rules when editing code

- **Routes vs nav:** Header links Home / Certifications / Experience / Projects / Contact. `/education` only redirects to `/certifications` (kept for old links); the Opensource page no longer exists. Splash is off (`isSplash: false`). The Certifications page renders CompetitiveSites + Certifications (no degrees).
- **Skill images:** files are requested as `skills/<imageSrc>?v=${skillAssetVersion}`. Overwriting or re-encoding a file under the same name **requires** bumping `skillAssetVersion` in [SoftwareSkill.js](src/components/softwareSkills/SoftwareSkill.js), or returning visitors keep the old image. A new filename is already a new URL (the code comment asks for a bump on every add too — harmless).
- **Reveal animations (react-awesome-reveal):** every `<Fade>` must keep `triggerOnce` — without it, elements re-hide and re-animate each time they cross the viewport, which caused violent scroll juddering (all 18 current usages have it). `Fade` wraps each child in its own `<div>`: when the animated element is a flex/grid item, put the sizing class on the Fade itself via `className` (see `.cert-card-reveal` in [CertificationCard.js](src/components/certificationCard/CertificationCard.js)) — sizing only the inner element collapses the layout.
- **Typography and text colours are owner-approved — don't drift them in refactors or a11y passes.** Font faces/weights/sizes match the July 2026 production build (Google Sans faces from `src/assests/fonts/`, Agustina logo, system font for body text, Experience accordion content at 14px/20px with descriptions in the system font, 404 page in the system font, tablet header at 12px). The secondary text colour stays `#7F8DAA` (~3.1:1 on the body, below WCAG AA) by the owner's choice — propose contrast changes, never apply them unasked. When replacing a component or library, compare rendered fonts before/after (e.g. headless Chrome `CSS.getPlatformFontsForNode`) instead of assuming equivalence.
- **Line height:** `body` uses an absolute `line-height: 23px` ([index.css](src/index.css)); any class with `font-size` above 23px must set its own `line-height` (~1.2) or wrapped lines overlap.
- **No Git LFS:** binaries are plain Git blobs (the account's LFS quota is exhausted) — never re-add `filter=lfs` rules. [scripts/verify-lfs-assets.js](scripts/verify-lfs-assets.js) stays as a guard: CI and the Pages build command fail if anything in `public/` or `src/assests/` is an LFS pointer (stale or broken checkout).
- **`.js` files hold JSX.** [vite.config.js](vite.config.js)'s `jsAsJsx` plugin (`enforce: "pre"`) esbuild-transforms every `.js` under `src/` (path-prefix match, not RegExp) as JSX before Rollup's import analysis; `optimizeDeps.esbuildOptions.loader` does the same for dev dependency scanning. Keep new component files under `src/` as `.js`; files outside `src/` (e.g. `scripts/`) are not JSX-transformed.
- **SEO test:** [src/seo.test.js](src/seo.test.js) asserts canonical/OG/JSON-LD and the OG template all use the apex. Keep it network-free and update it when the SEO source changes.

## Do not change on your own

- **`src/assests/` is misspelled on purpose** (not `assets`) and referenced that way everywhere — renaming it breaks every import.
- **`vite.config.js`'s `base: "./"` + `build.outDir: "build"`** control relative asset paths and output location (Cloudflare Pages expects `build/`). Vite ignores package.json's `"homepage": "."`, a harmless CRA leftover — don't rely on it and don't "clean it up" without checking both files stay consistent.
- **No `overrides` in package.json:** old hard pins blocked newer security fixes. Prefer `npm update <pkg>`; if an override is unavoidable, use a range (`^x.y.z`) and run `npm audit` after every lockfile change.
- **Vite stays on v7.** Vite 8 switches to the rolldown/oxc toolchain and drops the bundled esbuild that `jsAsJsx` depends on — upgrading broke both build and tests when tried. Don't bump the Vite major (and never run `npm audit fix --force`, which force-installs Vite 8) without first migrating the JSX-in-`.js` handling.
- **No service worker** (`src/serviceWorker.js` was deleted) — reintroducing one would break the deploy/cache expectations of Pages and the no-cache HTML behaviour.
- **Do not reintroduce Docker, nginx, Cloudflare Tunnel, self-hosted runner, `deploy.yml`, `deploy-worker.yml`, `cloudflare/` or `/healthz`.** They were deliberately removed with the Pages migration; the old runbook is only archived in `docs/legacy/`.
- **Do not add a portfolio subdomain.** The canonical and only public host is `https://yamiannephilim.com/`; `portfolio.yamiannephilim.com` must stay absent.
- **Deploy security:** this is a public repository. Never commit secrets or tokens; keep `main` protected with the required CI check; never add a deploy workflow that bypasses Pages or a PR-triggered self-hosted job.
